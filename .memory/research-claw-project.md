Research Claw is a research-paper reader (claude.ai-replica UI). Built in parts.

**Part A (DONE, 2026-06-26):** UI skeleton — sidebar (New chat, doc history, Google + dev-mock login/logout) + main window that renders uploaded PDFs like Chrome's viewer, recolored to Claude's warm palette (bg `#F5F4EE`, accent terracotta `#D97757`). Drag-and-drop upload, continuous-scroll virtualized viewer, Chrome-style toolbar, thumbnail rail. Works logged-out (anon `rc_anon` cookie) and logged-in (history persists; anon docs migrate to account on login).

**Stack:** Next.js 16 (App Router, Turbopack) + Auth.js v5 (JWT strategy) + Prisma 6 + SQLite + local file storage (`storage/uploads/`). react-pdf 10 / pdfjs 5, react-dropzone, @tanstack/react-query + react-virtual, zustand. Node installed via Homebrew (`/opt/homebrew/bin`); not on default PATH — prefix node cmds with `export PATH="/opt/homebrew/bin:$PATH"`.

**Non-obvious gotchas:** Auth.js Credentials provider (dev mock login, id `"dev"`) requires JWT sessions, not DB sessions. JWT type augmentation must target `@auth/core/jwt` (not `next-auth/jwt`). Next 16 renamed `middleware.ts`→`proxy.ts` (export `proxy`). pdfjs worker copied to `public/pdf.worker.min.mjs`, version-locked. Tests: Vitest (`npm run test`) + Playwright (`npx playwright test`, real-render check). Run with real Google OAuth by filling `AUTH_GOOGLE_ID/SECRET` in `.env.local`.

**Part B (DONE, 2026-06-26):** PDF text selection + persistent highlights (normalized rects, survive zoom/reload); mobile-style selection toolbar with a chat icon above the selection; floating Claude-style chat window per highlight ("window"), minimizes to a chip on the highlight (hover emphasizes the text). One persistent Claude session per PDF shared across windows; each message tagged windowId(highlightId)/turnIndex/seq.

**Part B Claude integration:** Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`, "Claude Code") authed with the DEVELOPER's Claude subscription via `claude setup-token` → `CLAUDE_CODE_OAUTH_TOKEN` (single shared account; per-user OAuth deferred). `src/server/claude.ts` wraps `query()` (model claude-opus-4-8, `systemPrompt` = research-assistant prompt + full extracted PDF text, `resume` per-PDF session id, `settingSources:[]`, `allowedTools:[]`, non-streaming — reads the `result` message). **Mock fallback** when the token is empty (or `CLAUDE_FORCE_MOCK=true`) so the whole flow works tokenless — this is the default in dev/tests. Per-document async mutex serializes turns (resume is single-flight).

**Part B gotchas:** `pdfjs-dist` must be in `next.config.ts` `serverExternalPackages` (server-side `extractPdfText` via the legacy build otherwise fails its fake-worker setup under Turbopack); `extractPdfText` needs a `Uint8Array`, not a Node `Buffer`. react-pdf text layer enabled in PdfPage + `react-pdf/dist/Page/TextLayer.css`. New Prisma models: ChatSession (per document, claudeSessionId, seqCounter), Highlight (window), ChatMessage. Integration via `DocChatContext`/`DocChatProvider`; per-page overlay = `PageChatOverlay` → `HighlightLayer` + minimized chips. Tests: Vitest (69) + Playwright `e2e/chat.spec.ts` (synthetic selection: build a Range over a `.react-pdf__Page__textContent span`, dispatch document `mouseup`).

**Part C (DONE, 2026-06-27):** replaced mock/subscription-token gating with **Anthropic API-key auth**. The user originally wanted per-user "log in with Google → authorize Claude Code with your Claude account" — but Anthropic **prohibits third-party apps from using claude.ai/subscription OAuth tokens with the Agent SDK** (Agent SDK docs: "Anthropic does not allow third party developers to offer claude.ai login... Please use the API key authentication methods"). So that flow is NOT buildable. Chosen instead: **BYOK + shared fallback** — resolution per chat = user's own stored key (billed to user) → shared `ANTHROPIC_API_KEY` env (billed to owner) → mock. API keys are not OAuth tokens, satisfying "no oauth tokens."

**Part C implementation:** kept the Agent SDK; `runClaudeTurn` now takes an `apiKey` and runs with `env.ANTHROPIC_API_KEY` (OAuth tokens stripped from the passed env), with retry-without-resume on resume failure (auth/session mismatch). `resolveClaudeAuth(owner)` in `src/server/claude.ts`. Per-user key stored encrypted (AES-256-GCM, `src/server/crypto.ts`, key from `APP_ENCRYPTION_KEY` or derived from `AUTH_SECRET`) in new `User.anthropicKeyEnc/Last4/UpdatedAt` columns. `src/server/services/claudeKey.ts` (get/set/delete/status + `validateAnthropicKey` = format gate + live GET /v1/models, lenient on network error, rejects 401). Routes `GET/PUT/DELETE /api/me/claude-key` (logged-in only; never returns the raw key, only connected+last4). UI: `ClaudeKeyModal` + "Connect Claude" entry in `UserMenu` (logged-in only); hooks `useClaudeKey`. Tests: 101 unit + 4 Playwright specs (incl. `e2e/byok.spec.ts`). Verified: no key→mock; bogus key→real Agent SDK call attempted (api.anthropic.com 401). To use real Claude: a logged-in user pastes their `sk-ant-...` key, or set shared `ANTHROPIC_API_KEY` in env.

**Part C v2 (SUPERSEDES the BYOK paragraph above, 2026-06-27):** the user rejected API keys and chose **account-based login via the Claude Code CLI**. Now: "Authorize Claude" → `claude auth login` relayed through the UI (open URL → paste code), per-user `CLAUDE_CONFIG_DIR`; chat runs `claude -p`. resolveClaudeAuth → account | sharedKey (env `ANTHROPIC_API_KEY`) | mock. Old BYOK files remain but are unreferenced. Full detail + the policy caveat in [[claude-auth-constraint]].

**Stale-session FK fix (2026-06-28):** a NextAuth session cookie can outlive its `User` row (dev DB reset while cookie persists). `resolveOwner()` trusted the session's userId, so writes (`document.create({userId})`, chat, highlights) hit "Foreign key constraint violated", and `prisma.user.update` hit P2025. Systemic fix in `src/server/owner.ts`: `resolveOwner` now `findUnique`s the User row and, if missing, **falls back to the anonymous identity** (rc_anon cookie) — so a stale session behaves as anon (can still upload/chat) instead of crashing. This generalizes the earlier per-route try/catch guards in the claude-auth routes.

**Scroll-to-page fix (2026-06-27):** jumping to a far page (page input or chat-history click → `requestScroll`) used to land near the top for pages >2. Two bugs: (1) `virtualizer.scrollToIndex` is unreliable for far *unmeasured* virtualized pages; (2) `consumeScroll()` was called at the START of the scroll effect → `scrollRequest=null` → effect cleanup cancelled the in-flight scroll. Final approach in `PdfViewer.tsx` scroll effect: **instant DIRECT jump** `stage.scrollTop = (page-1) * slot` (slot = renderWidth*aspect+GAP; exact for uniform-height PDFs — no animated walk), then a few silent snaps to the target page's real measured DOM offset for sub-pixel/mixed-size correction; `consumeScroll()` runs at the END. (An earlier viewport-by-viewport "walk" worked but felt buffery — replaced.) E2E guard: `e2e/chathistory.spec.ts` "jumping to a far page lands on that page". (Note: clearing `.next` may be needed if a killed dev server leaves a stale `.next/dev/types/validator.ts` that breaks standalone tsc.)
